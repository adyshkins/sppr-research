# Публикация без потери истории

Целевой существующий репозиторий: `adyshkins/sppr-prototype-back`, ID `1243562059`. При чтении main указывал на `897857750855167be9690bad89a375ba4d821fec` (коммит «v 1.0»). Сборка рассчитана на замену текущего дерева этого состояния, с сохранением прежнего сервера в `legacy/prototype-back/`.

## Текущий доступ

Чтение через подключение GitHub стало доступно после изменения видимости. Попытка создания дерева получила `403 Resource not accessible by integration`. Ни новое дерево, ни новый коммит этой сборки через это подключение не опубликованы. Из среды проверки также не разрешались DNS-имена GitHub и npm; переданные в переписке токены в исходники не записывались.

## Скрипт

На своём компьютере из распакованного исходного пакета:

```sh
python tools/publish.py
```

Это проверка без записи. Скрытый ввод токена используется только для запросов к GitHub. Для публикации и переименования:

```sh
python tools/publish.py --apply --rename sppr-research
```

Права токена должны разрешать работу с данным репозиторием, запись Contents и workflow-файла, а для переименования — Administration. Для classic PAT используются соответствующие scopes. При отказе не расширяйте доступ без необходимости; переименование можно отдельно выполнить в Settings репозитория.

Скрипт:

1. Проверяет SHA-256 файлов поставки и отсутствие токенов/закрытых ключей в публикуемом тексте.
2. Проверяет логин `adyshkins`, числовой ID репозитория и неизменность `main`.
3. Создаёт резервную ветку `backup/pre-monorepo-897857750855`.
4. Создаёт дерево и коммит с родителем — прежним main. Автор и коммитер: `Адышкин Сергей Сергеевич <adyshkinss@gmail.com>`.
5. Проверяет возвращённые поля авторства, повторно сверяет main и обновляет ветку только fast-forward.
6. Считывает опубликованный SHA и затем, при указанном параметре, переименовывает репозиторий.

Если main успел измениться, скрипт останавливается, а не стирает чужие изменения. История и отдельный `sppr-prototype-front` не удаляются. Если публикация прошла, а переименование нет, скрипт сообщает об этом отдельно: повторять публикацию не нужно.

Если репозиторий переименован заранее, используйте `--repo adyshkins/sppr-research`.

## Проверенные границы

Алгоритм публикации протестирован локальными подставными ответами API: dry-run, изменившийся main, несовпадающий автор, безопасное обновление ветки и проверка файлов. Реальная публикация и переименование из этой среды не выполнены.
