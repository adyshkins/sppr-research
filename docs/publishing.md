# Обновление опубликованного проекта

Рабочий репозиторий: `adyshkins/sppr-research`. Историю `main` сохраняем. Старые `sppr-prototype-back` и `sppr-prototype-front` не переименовываем и не изменяем.

## Одноразовое применение подготовленного патча

Из существующего локального клона проверьте, что нет незакоммиченных изменений. Затем:

```sh
git switch main
git pull --ff-only origin main
git am /path/to/SPPR_update_publishing.patch
git push origin main
```

Подставьте путь к скачанному патчу; пути с пробелами заключайте в кавычки. `git am` сохраняет автора патча, коммитером будет ваша локальная Git-учётная запись. Команды не используют force push. При конфликте не продолжайте отправку: `git am --abort` отменяет незавершённое применение патча. Уже успешно применённый патч повторно применять не нужно.

## Дальнейшая работа

Редактируйте код, просматривайте `git diff`, выполняйте проверки приложения из README и создавайте обычный коммит. Старые скрипты первоначального развёртывания и переименования больше не используются.

```sh
git status --short
git diff --check
python tools/verify_sources.py
# Выполните остальные проверки для изменённых компонентов.
# Добавляйте в индекс только проверенные файлы.
git add <reviewed-files>
git commit -m "Update project"
python tools/publish.py
python tools/publish.py --apply
```

Последняя команда необязательна: вместо неё можно выполнить `git push origin main`. Скрипт нужен для дополнительных проверок целевого репозитория и исходящих коммитов, а не для замены Git.

## Что проверяет publish.py

Скрипт работает только с существующим клоном и веткой `main`; рабочая папка и индекс должны быть чистыми. Единственные разрешённые URL назначения — HTTPS или SSH для `adyshkins/sppr-research`. Проверяются отдельно адреса чтения и отправки `origin`. Git сам выполняет аутентификацию через настроенное на компьютере средство авторизации; токен не запрашивается, не помещается в URL и не записывается в исходники.

Перед отправкой считывается удалённый `main`. Он должен быть предком локального коммита, иначе операция останавливается. Проверяются автор и коммитер всех новых коммитов: `AdSS`, `adyshkins` и `Адышкин Сергей Сергеевич` — имена одного владельца. Дополнительные строки соавторства требуют ручного рассмотрения. Паттерны токенов и закрытых ключей проверяются во всех новых снимках файлов и сообщениях коммитов, включая промежуточные версии. Это ограниченная проверка шаблонов, а не полный аудит секретов.

Отправляется только проверенный коммит в `refs/heads/main`, без тегов и force push. Обычная защита Git от non-fast-forward сохраняется и при конкурентной отправке другого коммита. После отправки сверяется удалённый SHA. Скрипт не меняет настройки автора, не создаёт коммиты, не переименовывает репозитории и не удаляет ветки. Проверка без `--apply` не меняет удалённый репозиторий, но выполняет fetch и обновляет локальные служебные данные Git.

## Контрольная ведомость поставки

`release-files.json` содержит SHA-256 файлов конкретной поставки, а не постоянный запрет на изменение проекта. При подготовке нового архивного выпуска ведомость нужно обновлять по фактическим файлам. Исторические хэши неизменённого ядра в `docs/upstream-files.json` не заменяются: они проверяются `tools/verify_sources.py`.

## Граница этого обновления

Изменены только средства публикации, их тесты, документация и правила окончаний строк. Версия приложения остаётся `0.3.0-dev`, вычислительное ядро — DEV-R08 0.8. Это не реализация F10/E11. Реальную отправку данного исправления можно считать состоявшейся только после проверки нового коммита на GitHub.
