# SPPR Research 0.3.0-dev — отчёт о сборке и проверке

Дата: 22 сентября 2026 года. Проверенная среда: Linux x86_64, Go 1.23.2, Node.js 22.16.0, Python 3.13.5.

## Что подготовлено

В один исходный проект объединены `backend/` (HTTP API и управление расчётами), `frontend/` (React/TypeScript), `engine/` (исходное ядро DEV-R08 версии 0.8) и `legacy/prototype-back/` (прежний демонстрационный сервер). Номер 0.3.0-dev относится к оболочке, а не к математической модели.

Интерфейс R08 позволяет выбрать профиль normal/S/C/D/DS, повтор 0–11 и варианты B0/H/EM/ET, создать расчёт, следить за его состоянием, получить фактические показатели и скачать первичные файлы. Повторное вычисление протоколов запускает исходный replay, а не только сравнение сводных чисел. Новые задания хранятся отдельно от исходного архива. HTTP API по умолчанию доступен только на loopback; для публичного развёртывания нужен отдельный проект защиты и аутентификации.

Сохранены проверка CSV E11, импорт и анализ сводок F10/E11, а также старый интерфейс MVP. Импортированные результаты, данные исходного архива и новые выполненные задания явно разделены. Текст статьи не используется для подстановки якобы вычисленных результатов.

Источник — `СППР_новая_реализация_08(2).zip`.

Проверка исходного полного манифеста завершилась сообщением о совпадении 2189 перечисленных файлов. Это не утверждение о файлах, отсутствующих в том манифесте.

В монорепозиторий перенесены без изменения байтов 154 исходных файла ядра и вспомогательных материалов, включая 91 Go-файл, модель, фикстуры и план 240 конфигураций. Контрольные суммы записаны в `docs/upstream-files.json`. Оригинальный README сохранён как `engine/README.upstream.md`; новый README поясняет отличия сокращённой исходной поставки от полного архива.

Полные исторические журналы не включены в исходный репозиторий: они остаются в пользовательском архиве. ### Новые вычисления R08 через HTTP API

Для окончательной версии backend выполнена контрольная выборка: повтор 0, пять профилей, четыре варианта — **20 эпизодов по 60 суток**. Каждый эпизод заново вычислен исходным CLI. Все пять первичных файлов каждого эпизода сопоставлены с SHA-256 из предоставленного архива и дополнительно скачаны через API с проверкой полученных байтов.

Итог: **100 из 100 первичных файлов совпали побитово с архивными образцами**; сводки также совпали. После расчёта выполнен исходный replay для всех 20 эпизодов — **1200 контроллерных записей**, без ошибок. Это повторение только указанной контрольной выборки, а не всех 240 эпизодов и не итоговых серий F10/E11.

Проверены шесть отрицательных HTTP-сценариев: недопустимый профиль, отсутствующая политика F, выход за диапазон повторов, неизвестное поле seed, запрет запуска F10/E11, отклонение постороннего Origin. После финальной правки декодирования проверены ещё семь запросов с отсутствующим/null repeat, дублирующимся полем, неверным корневым JSON и null вместо пустого объекта replay/cancel. Все отклонены ожидаемым кодом.

Перезапуск API восстановил пять ранее завершённых заданий с 20 эпизодами и сохранёнными статусами replay. Отдельно проверена поставляемая утилита `tools/check_r08_api.py` на нормальном профиле: четыре эпизода, 20 файлов, 240 replay-записей. Этот дополнительный smoke-test не включён в основные 20 эпизодов выше.

Машиночитаемые результаты находятся в `docs/verification/results.json` и отдельных JSON рядом. Повторение на своём компьютере после запуска API:

```sh
python tools/check_r08_api.py --output r08-check.json
```

### Границы проверки интерфейса

Штатная Vite production-сборка не завершена: исходный `node_modules` из Windows не содержит Linux-модуль `@rollup/rollup-linux-x64-gnu`; загрузка npm-пакетов была недоступна из-за DNS. Этот `node_modules` не включён в поставку. Lock-файл сохранён; установка для целевой платформы предусмотрена через `npm ci`, но успешный production-результат здесь не заявляется.

Браузерная HTTP-навигация к локальному серверу в среде проверки ограничена системной политикой. Для проверки компонентов использована отдельная автономная тестовая сборка и заранее полученные реальные JSON-ответы API, без сетевых запросов из браузера и без обхода этой политики. Проверены отображение R08, отключённый запуск F10/E11, реальные показатели и счётчики replay, ссылки первичных файлов, мобильная ширина 390 px, вкладки E11 и импорта, отсутствие JavaScript-исключений. Это проверка отображения, а не замена production-сборки или сквозного браузерного теста.

## Соответствие последней статье

Архив 0.8 содержит DEV-R08: 5 профилей × 12 повторений × 4 варианта B0/H/EM/ET = 240 конфигураций. Его CHECKPOINT ещё относит отложенные политики F/S/A/G и итоговую проверку к последующим этапам.

В статье после E11 описаны поздние F10 (840 эпизодов) и E11 (672 эпизода). Их исходная реализация, поздние конфигурации и внешний спросовой вход в предоставленном архиве 0.8 отсутствуют. Поэтому эта сборка не называется воспроизведением итоговой статьи. Реальный запуск R08 подключён; запуск F10/E11 остаётся явно недоступным. Новая оболочка не устраняет этот разрыв и не подменяет недостающий стенд приблизительной реконструкцией.

## Публикация и переименование

Чтение публичного `adyshkins/sppr-prototype-back` теперь доступно. Проверенный исходный main: `897857750855167be9690bad89a375ba4d821fec`. Попытка создать дерево через подключение GitHub вернула **403 Resource not accessible by integration**. Новые дерево, коммит и ветка не были созданы; репозиторий не переименован. Удалённый frontend-репозиторий не изменён. DNS GitHub в среде разработки также был недоступен.

В поставке подготовлен скрипт:

```sh
python tools/publish.py --apply --rename sppr-research
```

Он проверяет неизменность исходного main, создаёт резервную ветку, фиксирует автора и коммитера `Адышкин Сергей Сергеевич <adyshkinss@gmail.com>`, сверяет возвращённые поля и обновляет main без force push. Старые коммиты сохраняются. Переименование запрашивается только после подтверждённой публикации. Токен вводится скрыто в терминале и не сохраняется. Локальные тесты этого сценария не являются подтверждением реальной публикации; работающего GitHub Actions прогона пока нет.

Подробности — `docs/publishing.md`. Токены, node_modules, бинарные файлы, Git-история и локальное хранилище новых запусков не включены в исходный ZIP.

## Запуск

Полное приложение после установки зависимостей на целевой машине:

```sh
python tools/run.py --install
```

Только проверенный Go API и расчётное ядро, без Node.js:

```sh
python tools/run.py --api-only
```

Исходная поставка включает декларацию файлов `release-files.json` с SHA-256. Изменение любого перечисленного файла останавливает автоматическую публикацию до пересборки и повторной проверки поставки.
