# SPPR Research

**Автор: Адышкин Сергей Сергеевич.** Исследовательское приложение для сценарно-имитационного анализа интеллектуального контура управления.

Единый проект включает веб-интерфейс, локальный HTTP API, неизменённое вычислительное ядро DEV-R08 (версия 0.8) и прежний демонстрационный сервер. Версия оболочки — **0.3.0-dev**; она не обозначает новую версию математической модели.

> Сейчас реально запускается **R08: B0/H/EM/ET**. Исходный архив не содержит итоговую реализацию F10/E11 и политики отложенного пересмотра F/S/A/G. Импорт сводок F10/E11 доступен отдельно, но не подтверждает воспроизведение результатов статьи.

## Быстрый запуск

Нужны Go, Python 3.10+ и Node.js 22.12+ с npm. Ядро проверялось с Go 1.23.2; проверенные версии и ограничения текущей сборки перечислены в [отчёте](docs/verification.md). Первичная установка frontend-зависимостей требует интернета.

В PowerShell, терминале macOS или Linux из корня проекта:

```sh
python tools/run.py --install
```

Открыть `http://127.0.0.1:18081`. Скрипт проверит контрольные суммы ядра, соберёт Go-программы, установит frontend-зависимости по lock-файлу, соберёт интерфейс и запустит API со статикой. Остановка — Ctrl+C. При повторном запуске достаточно `python tools/run.py`; интерфейс пересобирается, чтобы не использовать устаревший bundle.

Без Node.js можно работать с API:

```sh
python tools/run.py --api-only
```

Для разработки интерфейса в отдельном терминале:

```sh
cd frontend
npm ci
npm run dev
```

API остаётся на `127.0.0.1:18081`, Vite — на `127.0.0.1:5173`. Публичное развёртывание без отдельной доработки аутентификации и защиты не предусмотрено.

## Возможности

**«Расчётный стенд R08».** Выбор одного из пяти профилей, номера повтора 0–11 и вариантов B0/H/EM/ET. Сервер выбирает конфигурации из неизменённого плана на 240 эпизодов, запускает настоящий `recoverycheck`, показывает прогресс, вычисленные потери и исполнения исключений. Параметры прогноза, seeds и риск-лимит через интерфейс не редактируются.

После завершения доступны повторное вычисление контроллерных протоколов (replay) и скачивание пяти первичных файлов каждого эпизода с SHA-256. Физический журнал и журнал контроллера разделены. Исходный архив не перезаписывается; новые данные находятся в `data/r08/`. Перезапуск API сохраняет завершённые задания и явно отмечает прерванные.

**«Внешний профиль E11» и «Результаты и анализ».** Проверка структуры и хэша внешнего CSV, импорт контрактных сводок F10/E11 и отдельный парный анализ. Они не запускают итоговые эксперименты и не являются заменой исходных журналов. Модельные потери не интерпретируются как рублёвый экономический эффект.

**«Прежний MVP».** Сохранён интерфейс старой СППР. Его отдельный сервер и PostgreSQL находятся в `legacy/prototype-back/`; для новых расчётов R08 они не нужны. Старый MVP не запускается основной командой. При его использовании отдельно согласуйте разрешённый frontend origin с выбранным адресом интерфейса.

## Структура

```text
backend/             HTTP API, импорт и анализ, управление процессами R08
frontend/            React / TypeScript / Vite
engine/              неизменённые Go-исходники 0.8, модель, фикстуры, план
legacy/prototype-back/ прежний backend, SQL и миграции
engine/scripts/      исходные исследовательские сценарии
tools/               запуск, контроль исходников, публикация
docs/                происхождение, ограничения, проверка и API
evidence/r08/        сводки и хэши из предоставленного архива
```

Полные исторические первичные журналы не включены в исходный репозиторий. Они остаются в пользовательском архиве `СППР_новая_реализация_08(2).zip`. В `evidence/r08/archive-summaries.json` сводки явно помечены как полученные из архива, а не как новые вычисления.

## Проверки

```sh
python tools/verify_sources.py
cd engine
 go test ./...
 go test -race ./...
 go vet ./...
cd ../backend
 go test ./...
 go test -race ./...
 go vet ./...
cd ../frontend
 npm run build
```

После запуска API контрольную выборку можно повторить отдельной командой:

```sh
python tools/check_r08_api.py --output r08-check.json
```

Она создаёт новые задания для повтора 0 по пяти профилям, сопоставляет 100 первичных файлов с архивными SHA-256 и запускает replay 1200 контроллерных записей. Исторические задания не удаляются. Для короткой проверки добавьте `--profiles normal`.

Для проверки `-race` нужен C-компилятор и поддерживаемая платформа. [Проверка перенесённого кода](docs/upstream-files.json) отделена от проверок новой оболочки. GitHub Actions запускает тесты и frontend-сборку, но наличие workflow-файла само по себе не означает, что CI уже отработал.

## Обновление опубликованного репозитория

Рабочий репозиторий — `adyshkins/sppr-research`. Начальная публикация выполнена; последующие изменения добавляются обычными коммитами поверх `main`. Переименование старого backend-репозитория и создание новой начальной истории больше не нужны.

После просмотра различий, тестирования и создания коммита из локального клона:

```sh
python tools/publish.py
python tools/publish.py --apply
```

Первая команда проверяет обновление без записи на GitHub. Вторая отправляет уже существующие локальные коммиты. Скрипт проверяет адрес `origin`, чистоту рабочей папки, ветку `main`, авторство исходящих коммитов и сохранение удалённой истории; использует обычную авторизацию Git и не запрашивает токен. Имена `AdSS`, `adyshkins` и `Адышкин Сергей Сергеевич` относятся к владельцу проекта. При изменившемся удалённом `main` сначала согласуйте истории; force push не применяется.

Обычный `git push origin main` также остаётся доступен. Подробности и порядок применения патча — в [инструкции](docs/publishing.md). Служебный скрипт не создаёт коммитов и не меняет исследовательское ядро.

## Методологическая граница

R08 — разработочная синтетическая серия. Разрешённое исключение EM/ET не становится риск-допустимым; реального экспертного согласования и управления оборудованием нет. Перенос ядра в веб-приложение не изменяет этот статус. [Сопоставление с последней статьёй](docs/research-status.md).
