# СППР: новая реализация 0.8

**Это исследовательский вычислительный стенд, не система промышленного управления.** Новая ветвь строится на проверенном коде 0.6 и документированном правиле E из отчётов 0.7. Полных исходников 0.7 в рабочем окружении не было. Код и данные не являются восстановлением старых утраченных диссертационных прогонов.

## С чего начать

- `docs/23_findings_v0_8.md` — результат исследования реакции на `RISK_EMPTY`.
- `docs/21_recovery_protocol_v0_8.md` — зафиксированный до запуска дизайн.
- `docs/22_recovery_method_v0_8.md` — математическая модель исключения и её ограничения.
- `docs/24_verification_v0_8.md` — фактические проверки, журналы и исправления.
- `results/recovery_v08/analysis/RESULTS.md` — все варианты и парные интервалы.
- `results/recovery_v08/references/RESULTS.md` — независимые продолжения, включая все пропуски.
- `CHECKPOINT.md` — контрольная точка для следующей работы.
- `RELEASE_CONTENTS.json` — состав именно этого архива; `MANIFEST.json` проверяет только включённые файлы.

## Что добавлено

`evidenceinit` заново реализует E без резервной амплитуды отсутствующего признака. `recovery` сохраняет первоначальный отказ и создаёт **отдельное, не риск-сертифицированное предложение**. `recoverycontrol` связывает его с наблюдениями и прогнозом; `recoveryrun` исполняет и протоколирует эпизоды и replay. В исходные 80 Go-файлов 0.6 изменения не внесены.

Восстановительное назначение не выполняется без двух явных разрешений: исследовательского исключения и режима без экспертного ожидания. В обычном режиме требуется рассмотрение. `risk_certified=false`, исходный CVaR и превышение лимита сохраняются; жёсткие разрешения перед исполнением проверяются снова. Автономное применение к реальному оборудованию не предусмотрено.

## Требования

Проверено с Go 1.23.2, Python 3.13.5, NumPy 2.3.5, Linux amd64. Go-код не требует сторонних модулей. `go test -race` дополнительно требует поддерживаемой платформы, CGO и C-компилятора. Другие версии и Windows не проверялись; переносимый запуск использует PATH и абсолютные пути.

Из корневой папки:

```text
go test ./...
go vet ./...
go test -race ./...
python scripts/verify_release_manifest.py
```

Быстрая повторная генерация четырёх согласованных эпизодов S (никакие старые файлы не заменяются):

```text
python scripts/reproduce_recovery_v08.py smoke --out rerun_smoke
```

Запуск всех 240 эпизодов в новую папку:

```text
python scripts/reproduce_recovery_v08.py all --out rerun_all --workers 4
```

Запуск имеет значительные затраты времени и места. По умолчанию создаётся новый комплект в `rerun_all/series`, включая копию плана и первичные журналы. Исходная серия не перезаписывается. В уменьшенном архиве код, модель и обучающие данные есть; пропущенные первичные результаты будут получены заново.

Повторное вычисление по сохранённым наблюдениям (требует полного архива):

```text
python scripts/reproduce_recovery_v08.py replay --out replay_check
```

Для заново сгенерированной серии:

```text
python scripts/reproduce_recovery_v08.py replay --suite rerun_all/series --out replay_new_check
python scripts/reproduce_recovery_v08.py references --suite rerun_all/series --out reference_new_check
```

Проверка 20 эпизодов против архива:

```text
python scripts/reproduce_recovery_v08.py regenerate20 --out regeneration_check
```

Генератор сохраняет независимые потоки среды и прогнозов. Битовая идентичность установлена в проверенном окружении; на других версиях нужно отдельно оценить расхождения, а не игнорировать их.

## Независимый пересчёт имеющейся серии

В полном архиве из корня:

```text
python scripts/audit_recovery_v08.py
python scripts/analyze_recovery_v08.py
python scripts/analyze_reference_recovery_v08.py
```

Для аналитики нужен NumPy (использованная версия записана в `requirements-analysis.txt`). Эти три исторических скрипта ориентированы на `results/recovery_v08` и при запуске заново записывают соответствующие отчёты. Перед их запуском сохраните исходный архив; после пересоздания отчётов действующие контрольные суммы выпуска нужно сравнивать с пониманием этих изменений. Хранящиеся в журналах абсолютные пути описывают реальное окружение исходного запуска. Для пользовательского запуска используйте `reproduce_recovery_v08.py`, а не исторические исполнители с `/mnt/data` в параметрах по умолчанию.

## Границы результата

DEV-R08 — 12 согласованных повторений пяти профилей, четыре варианта, 240×60 суток. Это разработка после анализа предыдущих серий. В обычном режиме H действует риск-фильтр; EM/ET исследуют последствия отдельно разрешённого исключения, а не «новую гарантию» того же фильтра. Все варианты используют синтетическую модель. Нет результатов внедрения, реального экспертного одобрения, денежного эффекта или окончательной независимой проверки.

Статус источников, описание неудачного первоначального `go vet`, механической правки и повторных проверок не удалены. Старые `README_v0_*.md`, `CHECKPOINT_v0_*.md`, `MANIFEST_v0_*.json` являются историческими; для текущего содержимого используется только `MANIFEST.json`.
